# 対戦の概念整理（シングル・ポケモンチャンピオンズ）

構築・選出・対戦中の判断で使う観点の定義。タグ名（英字）は engine 側の分類と共通にする予定。

## 1. ルール前提（レギュレーションMC / シーズンM-6時点）

- 6体見せ合い→3体選出。Lv50固定
- メガシンカあり（1試合1回）。テラスタルなし
- 個体値なし（全ステータス従来の31相当）
- 能力ポイント: 合計66、1ステータス最大32、1ポイント=実数値+1
- 実数値: HP=種族値+ポイント+75、他=(種族値+ポイント+20)×性格補正（切り捨て）
- 時間: 選出90秒、1ターン45秒、持ち時間7分、総合20分
- 出典と更新方法: docs/spec.md の「情報源」

## 2. ポケモン単体を見る軸

| 軸 | 見るもの | 判定の目安 |
|---|---|---|
| 攻撃の型 `phys`/`spec`/`mixed` | A と C の種族値、採用技の分類 | ちからもち・ヨガパワーはAを2倍で比較 |
| 耐久の型 `bulk_phys`/`bulk_spec` | H×B、H×D | 両方高い=総合耐久、片方=物理/特殊受け |
| 速度帯 | 最速・準速の実数値、スカーフ・メガ後 | 同速帯・抜き抜かれは素早さタブで確認 |
| タイプ | 弱点・半減・無効の数 | knowledge/types.md |
| 役割 | 下表のタグ（複数可） | 型（技・持ち物）で決まる。種族だけでは決めない |

## 3. 役割タグ

| タグ | 呼び方 | 定義 | 典型的な技・持ち物 |
|---|---|---|---|
| `ace` | エース・全抜き | 積んで・通して最後まで倒し切る駒 | 積み技、きあいのタスキ、いのちのたま |
| `breaker` | 崩し | 受けを突破する高火力・崩し技持ち | 高威力技、状態異常対策 |
| `faceoff` | 対面駒 | 1対1で勝つ前提の駒 | タスキ、先制技、スカーフ |
| `cushion` | クッション | 相手の攻撃を1回受けて後続につなぐ | 高耐久、再生技、とんぼがえり |
| `wall_phys`/`wall_spec` | 物理受け・特殊受け | 特定の相手を繰り返し受ける | 回復技、おにび、どくどく |
| `setter` | 起点作り | 壁・ステルスロック・あくび等で後続を通す | ひかりのねんど、ステルスロック |
| `stopper` | ストッパー | 相手のエースを止める | 先制技、スカーフ、カウンター系 |
| `pivot` | サイクル要員 | 交代で有利を取り直す | とんぼがえり、ボルトチェンジ、さいせいりょく |
| `weather`/`terrain` | 始動役 | 天候・フィールドを展開 | 特性、しめったいわ等 |

## 4. 構築の型

| 型 | 勝ち筋 | 必要な役割 | 弱点 |
|---|---|---|---|
| 対面構築 | 1対1を連勝して数的有利 | `faceoff` 中心、タスキ・スカーフ・先制技 | 交代読み、耐久の高い受け |
| サイクル構築 | 交代で有利対面を作り続け削る | `cushion` `pivot` `wall_*` | 崩し、積みエース、時間 |
| 展開構築 | 起点作りから積みエースで全抜き | `setter` + `ace` | 起点作りを潰される、ストッパー |
| スタンダード（スタンパ） | 対面・サイクル・崩しの併用 | 各役割をバランスよく | 構築理解と判断量が要る |
| 受けループ | 受けと定数ダメージで勝つ | `wall_*` 複数 + 回復 | 崩し・積み・時間切れ |

英語圏の分類との対応: Hyper Offense≒展開、Bulky Offense≒対面寄りスタンダード、Balance≒スタンダード〜サイクル、Stall≒受けループ。

## 5. 判断に使う用語

- 確定n発: 16通りの乱数すべてでn発以内に倒せる。乱数n発: 一部の乱数でのみ倒せる（確率を併記）
- 耐久調整: 特定の攻撃を確定数で耐えるように能力ポイントを振ること（例: 「A特化ガブリアスのじしんを確定耐え」）
- 最速/準速: 性格補正あり/なしでSに32振り
- 通り: その技・ポケモンが相手の並びに対して有効な数
- 並び・補完: 互いの弱点をカバーするタイプ・役割の組み合わせ
- 選出誘導: 見せ合いで特定の選出を強いる並びの作り方

## 6. 3体選出で意識すること

- 見せ合いの6体から、相手の先発・エース・ストッパーを推定する
- メガシンカは1試合1体。メガ持ちを2体選出すると片方は通常の姿で戦う
- 選出予想の現在の実装: docs/spec.md の「選出予想」参照（通り×使用率のルールベース）
