# 仕様（v0.1）

## 目的

ポケモンチャンピオンズのシングル対戦で、プレイヤーが知識・経験として持っている情報（型、ダメ計、素早さ、選出の読み）を、対戦とは別の端末（このPC）で素早く引き出せるようにする。

- リアルタイムに画面を読み取って自律的に戦術を決める設計にはしない
- 本体はコード。AIは実装と、一部の自然言語生成（リサーチ結果の要約・回答）にのみ使う
- AIとの連携は、状況をフォルダに書き出し、Claudeアプリのチャットから読んで答える方式を基本にする（API課金なし・他のAIでも読める）

## 決定事項

| 項目 | 決定 |
|---|---|
| 対象ルール | シングルのみ |
| 実行環境 | このPC上のローカルWebアプリ（ブラウザで開く）。ネット接続あり |
| 相手6体の入力 | 名前検索の手入力。スクショ判定は後日、Claudeのチャットから state/opponent.json に書き込む方式で追加 |
| 環境データ | 最新シーズンのみ保持。推移は持たない |
| 選出予想 | ルールベースの結果を即時に出し、不足データの取得を並列で走らせて、取れたら再計算 |
| 自分のパーティ | 複数保存。名前・構築の型を持つ。選出・ダメ計は選択中のパーティを使う。自動保存（0.5秒後）＋手動保存ボタン、画面を閉じる前に未保存分を送信 |
| メガシンカの入力 | ポケモン名の候補にメガ〇〇は出さない。メガ進化があるポケモンは「メガシンカ枠」（1種ならチェック、X/Y・Zなど複数ならセレクト）で指定し、持ち物はメガストーンを自動入力して固定。通常の持ち物候補にメガストーンは出さない |
| 型を自動入力 | 入力済みの項目は変えず、未入力の性格・特性・持ち物・能力ポイント（合計0のとき）・技の空き枠を環境データの採用率上位で埋める。物理/特殊は入力済みの能力ポイント→性格→技→メガ後の種族値の順で判断し、合う性格・配分・技だけを選ぶ。環境データにそのポケモンが無い、または入力済みの性格・特性・持ち物・技がどれも上位に無いときは埋めない |
| 能力ポイント入力 | 各ステータスに「0」「Max」（32か残りポイントの小さい方）ボタン。パーティとダメ計で共通 |

## 新UI（simple）

`python -m app --ui simple` で起動する、対戦の流れ（パーティ → 選出 → ダメ計、別枠でタイプ相性）に絞った画面。現行UIは `python -m app`（既定）のまま。サーバ（`app/server.py`）は環境変数 `APP_UI` で配信元を `app/static`（現行）と `app/static_simple`（新）に切り替えるだけで、`/api/*` と `engine/`・`data/user/` は共通。

- ビルド不要のES Modules（`app/static_simple/js/pages/*.js`、見た目は `css/tokens.css` と `css/app.css`）
- 画面の入り口は初心者向けに「いま何をするか」を一行で案内し、用語は「？」で説明する
- 入れていない機能（対戦記録・逆算、素早さ表、図鑑・型、履歴、構築診断・調整）は現行UIで使う

## 画像からのパーティ取り込み（screenreader/）

ゲームの「パーティ確認」画面（能力タブ・ステータスタブ）のスクショから6体の型を読み取る。外部APIには依存せず、端末内のOCRと辞書・実数値の整合性だけで決める（ルールベース）。新UIのパーティ画面「画像から取り込む」と `POST /api/team/import-image`（base64の画像を渡すと読み取り結果を返す。登録はUI側が既存のAPIで行う）。

- OCR: `screenreader/ocr.py`。macOS は Vision（pyobjc）、それ以外は tesseract（日本語データ jpn が必要）。差し替え可能
- レイアウト: `screenreader/layout.py`。端末・プラットフォームごとにカードの位置・大きさ・余白が違うため、固定の座標は使わず、画像から6枚のカード（紫の角丸パネル）を色の射影で検出し、カード内の位置はカードの大きさに対する相対値で写す。検出できないときだけ基準レイアウト（2532x1170）の拡縮で代用し、警告を返す
- タブの判定も、カードの上の黄緑の位置（左右）で行う。数字は、その種族の実数値としてありうる範囲に収まるまで、しきい値・切り出し幅を変えて読み直す
- 新しい端末で外れたら `python tools/debug_screen.py 画像.png` で、カード・各セルの位置を描いた画像を出して layout.py の相対値を調整する。確認済み: スマホ(2532x1170)と別プラットフォーム(1920x1080)、引き伸ばし・縮小
- 能力タブ: 名前は全ポケモン名、特性は種族の特性、技は種族の覚える技の辞書へ曖昧一致（濁点・小書き・長音の誤認識を吸収）
- ステータスタブ: 各セルの数字を読み、▲（赤）▼（青）のアイコン色から性格の候補を決め、実数値と合う能力ポイントを逆算する（アイコンが読めなければ25性格を実数値で総当たり）
- 読み取れない・曖昧な項目は `flags` で返し、UIで黄色の注意として出す
- 回帰: tests/test_screenreader.py（実機スクショ2種は tests/fixtures/、引き伸ばし・縮小も含む。OCRが使えない環境ではスキップ。約40秒）

## 構成

```

data/snapshots/     環境データ（L3）。current/usage.json が最新シーズン
data/user/          自分のパーティ（L4）。teams/<id>.json に1パーティ1ファイル、settings.json に選択中のid
engine/             実数値・ダメ計・型推定・対面評価・選出予想（純粋な計算）
collectors/         情報源アダプタ（サイトごと）とバックグラウンドジョブ
app/                FastAPIサーバとUI（app/static）
state/              Claudeが読む現在の状況（current.md が入口）
knowledge/          LLM向けの概念整理・相性表・性格表
tools/              データ生成・検証スクリプト
```

## 選出予想（ルールベース v0.2）

1. 相手の型: 環境データの採用率上位。最多の性格から物理/特殊を決め、それに合う能力ポイントと攻撃技（上位4）を選ぶ。無ければ種族値からの推定型
2. 対面評価: 自分i vs 相手j で互いの最大打点から「50%以上の確率で倒せる発数」を出し、発数と素早さで分類する。1=有利（発数が少ない、または同じ発数で先に動く）、0.75=有利だが後攻で発数の差が1以下、0.5=同じ発数で同速、またはどちらも倒せない、0.25=不利だが発数の差が1以下、0=不利
3. 相手の選出スコア = 自分のパーティへの通り（対面評価の平均）×0.5 + 使用率順位（1位=1、60位以下≒0）×0.5
4. 推奨選出 = 3体の全組み合わせ20通りについて、相手各体への最良の駒のスコアを相手の選出スコアで重み付けして合計。メガ持ち2体は減点
5. 相手の中に環境データが無いポケモンがいれば、その場で取得ジョブを投げ、完了後に再計算して state/ を更新
6. 実戦データ補正: 相手の「倒されたポケモン」上位10に自分の駒がいれば加点、「倒したポケモン」上位10にいれば減点（順位で重み付け、最大±0.15）。使用率の高いポケモンは両方に出やすいので差し引きで打ち消す
7. 受け出し先: 相手の最大打点が50%未満の自分の駒（2回受けても倒れない）
8. 積み: 相手が採用率30%以上で積み技を持つ場合、1回積んだ後の対面を再計算し、有利から不利に変わる駒を「起点にされる」と表示

既知の限界: 交代の連鎖・状態異常・壁の展開は評価しない。相手の型は1通りしか仮定しない。使用率データは種族単位なので、メガシンカ後の型（例: メガガブリアスZは特殊寄り）と通常の型が混ざる。

## 動作の安定化

- `python -m app` はコード（app/engine/collectors）の変更を検知して自動で再起動する
- 画面のHTML・JS・CSSはキャッシュさせず、JS/CSSのURLに内容のハッシュを付ける（古い画面が残らない）
- 画面(app.js)とサーバの世代番号（APP_API_VERSION / API_VERSION）が違うと、画面上部に再起動を促す帯を出す。JSのエラーやサーバの500も同じ帯で知らせる

## 対戦記録と逆算ダメ計（v0.1）

保存: data/user/matches/<id>.json に1対戦1ファイル。相手の6体（opp）と、対戦モードを使ったときだけ detail（自分のパーティのコピー、選出、記録、結果、メモ）。現在の対戦は data/user/settings.json の current_match。Claude向けに state/battle.md を書き出す。

記録の種類:

| 種類 | 必須 | 任意（未入力は「なし」として計算し、未確定と表示） |
|---|---|---|
| 被ダメ（相手→自分） | 相手・自分・相手の技・受けた後のHP（実数） | 受ける前のHP（既定は最大HP）、倒れた、急所、天候、フィールド、相手の攻撃ランク、自分の防御ランク、相手のやけど、自分側の壁、相手のメガシンカ、連続技の回数 |
| 与ダメ（自分→相手） | 相手・自分・自分の技・当てた後の相手HP（%） | 当てる前の%（既定100）、ほか同上（攻守を入れ替えた意味） |
| 判明 | 相手・種類（持ち物/技/特性）・内容 | なし |

逆算の手順（残りHP・%が0の記録は「倒れた」として扱う）:
1. 記録ごとに、性格補正（↑/無/↓）×該当ステータスの能力ポイント（0〜32）×持ち物候補×特性候補を全列挙し、観測値を再現できる組み合わせを残す。被ダメはHP実数が16乱数のどれかと一致、与ダメは%の差が±1（当てる前が満タンでない場合±2）以内
2. 持ち物候補は「ダメージに影響しないもの（その他）」＋採用率上位のうち火力・耐久に影響するもの＋いのちのたま・たつじんのおび＋技タイプの強化アイテム・半減実。判明した持ち物・特性があればそれに固定
3. 同じ相手の記録を25性格×持ち物×特性ごとに同時に満たすか調べる（HPは耐久側の記録で共有、合計66以内）
4. 残った候補を採用率で重み付けし、最有力の性格・持ち物・特性と能力ポイントを推定。能力ポイントは候補範囲に収まる採用率上位の配分を優先
5. 相手の型の表示: 判明情報と記録で使われた技は「確定」、逆算で決めたものは「逆算」、残りは「採用率」（環境データ）か「推定」（種族値）

現在の対面（detail.live）: 自分はHP実数、相手はHP%、状態異常（やけど・まひ・どく・もうどく・ねむり・こおり）、A/B/C/D/Sのランク、相手のメガシンカ（未確定＝採用率どおり想定／した／しなかった。しなかった場合はメガストーン以外の型で表示し、誰かがメガシンカしたら他は自動で「しない」扱い）、場（天候・フィールド・両陣営の壁）。新しい記録の条件はここから作る（技の物理/特殊に合わせて攻撃側A/C・防御側B/Dのランクと、該当する壁を選ぶ）。記録の追加後、受けた/当てた後のHP（倒れたら0）と、状態異常技の結果（例: でんじは→まひ）を反映。条件を個別に直したいときは記録一覧の「編集」。

連続技は1発ごとに乱数を独立に引いた合計で照合する。回数が未入力なら、ありうる回数（2〜5回技なら2〜5回）をすべて候補にする。おやこあいの回数は当たった発数（未入力は2発）。

既知の限界: 乱数・%表示の丸めで1回の記録では幅が広い（記録を重ねるほど絞れる）。きのみの消費・特性の発動条件（マルチスケイルは満タンのときのみ適用）は近似。候補0通りの記録は赤く表示するので、入力値か条件を見直す。

## ダメージ計算

第9世代の計算式を Showdown と同じ丸め順で実装。2026-10-05 に最新の Showdown（champions mod、BSS Reg M-C）と同条件で比べたランダム15,500ケースで、比較用テスト環境で再現できない効果（へんしん・トレース・みらいよち・ばけのかわ・ジュエル）を除き16乱数がすべて一致。一致したケースのうち1,076件を回帰テストとして tests/fixtures に保存（おやこあいは1発目を比べる）。

比べ方: `python tests/fuzz_cases.py <件数> <seed> cases.json` → `node tools/verify_with_showdown.js <ビルド済みShowdown> cases.json > ref.json`（Node 22以上） → `python tests/fuzz_compare.py cases.json ref.json`。

対応している主な補正: タイプ一致・相性・急所・乱数・やけど・天候・フィールド・壁・ランク・主要な特性（ちからもち、テクニシャン、かたいツメ、スキン系、ドラゴンスキン、メガソル、ファイアマネ、マルチスケイル、ハードロック、あついしぼう、ファーコート、オーラガード、ノーてんき、ぎたい、てんきや、ぶきよう、ひとでなし、じゅくせい、はりきり、ロングリーチ等）・持ち物（いのちのたま、たつじんのおび、タイプ強化、半減実、くろいてっきゅう 等）・威力変動技（けたぐり、ヘビーボンバー、ふんか、はたきおとす、ジャイロボール 等）・サイコフィールドでの先制技の無効。イカサマは相手の攻撃に自分の特性・持ち物の補正をかける（Showdown と同じ）。

連続技・おやこあい: 1発ごとに乱数を独立に引く。表示の最小・最大は正確で、確定数（乱数n発）は全組み合わせから出す。おやこあいの2発目は基本ダメージの1/4。

素早さ: ランク→スカーフ・くろいてっきゅう・はやあし・天候/フィールドの特性（すいすい、サーフテール等）・かるわざの補正を連結→まひ半減（はやあしは半減なし）。ノーてんきがいると天候の特性は働かない。

未対応（手入力で補う）: アナライズ、とうそうしん、はりこみ、へんげんじざい・ぎたい以外のタイプ変化、ばけのかわ、ジュエル以外の消費系持ち物の発動、条件付き威力（しっぺがえし等）は「威力を手入力」を使う。

チャンピオンズの状態異常（変化技の説明文に反映）: まひで動けない確率は1/8、ねむりは1〜2ターン（2ターン目に起きる確率1/3）、こおりは最大3ターン。

## 構築診断の判定基準（v0.1）

| 役割 | 判定 |
|---|---|
| エース | 積み技を持つ |
| 起点作り | ステルスロック・まきびし・壁・あくび・トリックルーム・おいかぜ・ちょうはつ等、またはひかりのねんど |
| サイクル要員 | とんぼがえり・ボルトチェンジ等の交代技、またはさいせいりょく |
| ストッパー | 先制攻撃技、またはこだわりスカーフ |
| 対面駒 | きあいのタスキ・がんじょう・マルチスケイル・ばけのかわ、またはAかCとSに28以上振った積み技なしの駒 |
| 物理受け・特殊受け | 回復手段（回復技・たべのこし・オボンのみ・さいせいりょく）があり、H×B（H×D）が26,000以上かHとB（D）に計50以上振り |
| クッション | 受けに該当せず、耐久に計40以上振りか両耐久指数24,000以上 |
| 崩し | 積み技なしで、火力アイテムかメガシンカ、かつAかCに28以上振り |
| 天候・フィールド始動 | ひでり・あめふらし・すなおこし・ゆきふらし・各サーフ・メガソル、または天候/フィールド技 |

構築の型ごとの必要数: 対面=対面駒かストッパー2体以上、サイクル=サイクル要員1体＋クッション/受け2体、展開=起点作り1体＋エース1体、スタンダード=エース/崩し・クッション/受け/サイクル要員・ストッパー/対面駒を各1体、受けループ=物理受け1体＋特殊受け1体。

タイプの重なりは、同じ攻撃タイプの弱点が3体以上で表示（半減以下が0体なら要確認）。特性による無効（ふゆう・もらいび等）は考慮する。
