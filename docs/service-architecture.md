# サービス公開の構成（v0.3・MVP実装済み、公開前）

サービス名: ギャクダメノート（英字表記: Gyakudame Note）

ローカルアプリ（`python -m app`）を、アカウント付きのWebサービスとして公開するための構成。課金はまだ入れないが、入れるときに作り直さない形にする。

## 前提と方針

- 計算の本体（engine/）は今のPythonをそのまま使う。ダメ計はShowdownとの一致テスト（1,076件）があるので、作り直さない
- 画面（app/static）も今のES Modulesを使う。ビルドなしのまま、ログインとデータの保存先だけ差し替える
- ローカル版（Claudeがstate/を読む使い方）は残す。サービス版と同じコードで、保存先だけが違う
- 環境データは運営者だけが更新する。利用者の操作で外部サイトへ取りに行くことはしない
- 個人情報は「ログインに必要なメールアドレス」以外を持たない

## 全体像

```
ブラウザ（app/static + supabase-js）
  ├─ ログイン ───────────────→ Supabase Auth（Google／メールのワンタイムコード）
  ├─ パーティ・設定の読み書き ─→ Supabase Postgres（RLSで本人の行だけ）
  └─ 計算・対戦の操作（JWT付き）→ Vercel Functions（Python / FastAPI、engine/ をそのまま使う）
                                    └─ 利用者のJWTで Supabase を読み書き（RLSがそのまま効く）
運営者のPC: collectors/ で環境データを取得 → git push → Vercel が再デプロイ（データはコードと一緒に配る）
```

| 役割 | 使うもの | 理由 |
|---|---|---|
| 画面の配信 | Vercel（静的ファイル） | 今の画面がそのまま載る |
| 計算API | Vercel Functions（Python、FastAPI。設定なしで動く） | engine/ を書き直さない。Pythonの関数は展開後500MBまで、最大実行時間300秒（Hobby） |
| 認証 | Supabase Auth | Google・メールのワンタイムコードが標準。パスワードを持たない |
| データ | Supabase Postgres（東京リージョン） | RLSで「本人の行だけ」をDB側で保証。上限（プラン）もDB側で守る |
| 環境データ | リポジトリに同梱（usage.json） | 実行時に外部へ取りに行かない。版が残る |
| 課金（将来） | Stripe Checkout＋Webhook（Vercel Functions） | Webhookでプランを書き換えるだけで制限が変わる |

Vercelの関数は東京（hnd1）に置き、Supabaseも東京にする（往復を短くする）。

## データベース

```
profiles      user_id(PK, auth.users) / plan(既定 'free') / created_at          ← 名前・アイコンは持たない
plan_limits   plan(PK) / max_teams / max_matches / features(jsonb)              ← 制限はデータ。プランの変更はここだけ
teams         id / user_id / name / archetype / members(jsonb) / updated_at   ← 今の data/user/teams/*.json と同じ形
user_state    user_id(PK) / active_team_id / current_match_id / opponent(jsonb) / prediction(jsonb)
matches       id / user_id / created_at / opp(text[]) / team_name / detail(jsonb) ← 今の matches/<id>.json と同じ形
subscriptions（将来） user_id / stripe_customer_id / status / plan / current_period_end ← Webhookだけが書く
```

- すべての表に RLS（`user_id = auth.uid()`）。ブラウザからは公開キーだけを使い、管理用キーはWebhook以外で使わない
- 上限はトリガーで守る: パーティは `max_teams` を超えたら追加を拒否、対戦履歴は `max_matches` を超えたら古いものから消す（どちらにするかは後で変えられる）
- 機能の制限（例: 逆算・控え相性）は `plan_limits.features` を画面とAPIの両方で見る
- アカウント削除で全行を消す（`on delete cascade`）。データの書き出し（JSON）も用意する

## コードの変え方

- `app/storage.py`: 保存先の差し替え口。ローカル版は `FileStore`（今のファイル）、サービス版は `service/supabase.py` の `SupabaseStore`（利用者のアクセストークンでPostgRESTを呼ぶ）
- サービス用の入口 `service/main.py`（FastAPI）。`app/server.py` の /api（APIRouter）をそのまま取り込み、ログインの確認と保存先の切り替えだけを足す
- 画面は `/api/config` で版を知り（`store.js` の `isService()`）、サービス版ではログイン画面（`auth.js`）・アカウント画面を出し、ローカル版だけの機能を隠す
- 逆算のキャッシュは関数の中に残る（同じ実体が続けて使われる間は速い）。初回だけ1〜数秒かかることがある

## 画面: 流用か作り直しか

今の画面は JS 約129KB（1行が長い書き方。一般的な書式なら約4,000行）、7画面、API 21種類、DOMの組み立て約750か所。画面のテストは無い（表示の確認1件のみ）。

| 観点 | 今の画面を流用 | Next.js（React・TypeScript）で作り直し |
|---|---|---|
| 公開までの工数 | 小。画面はすべて `/api` 経由でデータを扱い、ファイルを直接触らない。変えるのは `api()`（1か所）に認証ヘッダを足す・ログイン画面・アカウントメニュー・上限に達したときの表示だけ（作業1〜2回分） | 大。7画面を作り直し、対戦の記録フォーム・保存待ちの変更・未保存の確認・スクロール位置などの細かい動きを再現する（流用の5〜10倍） |
| 動作の同等性 | 今のまま（ここ数日で直した細かい挙動も残る） | 画面のテストが無いので、同じ動きかを手で確かめる必要がある。取りこぼしの危険が大きい |
| 構成 | 静的ファイル＋Python関数。ビルド不要 | Next.js と Python関数の2つのランタイムを1プロジェクトに置く。ビルド・型・依存の更新が増える |
| 公開後の修正 | 型が無く、画面の状態がモジュール変数に散っている。画面が今の倍以上になると直しにくくなる | 型・部品化で大きな機能追加がしやすい。外部の部品（認証・決済のUI）も多い |
| 課金への影響 | 小。決済はStripeの決済ページへ移るだけで、通知の処理はサーバ側 | 同じ（サーバ側の作業は変わらない） |
| SEO | 不要（ログイン後の道具）。紹介ページ・規約は静的HTMLで足りる | SSRの利点はあるが、この用途では効かない |

結論: **流用する**。公開を早め、今の動作をそのまま保つ。修正の手間を抑えるため、次を合わせて行う。

- ビルドなしのまま型チェックを入れる（JSDoc＋`// @ts-check`）
- 画面は `render(view)` を持つ独立したモジュールなので、必要になった画面から順に別の作りへ置き換えられる（一度に作り直さない）
- 主な操作の画面テスト（Playwright）を足し、置き換えるときの同等性の確認に使う

## MVPに入れるもの・入れないもの

| 入れる | 入れない（後で） |
|---|---|
| Googleでログイン、ログアウト、アカウント削除 | 画像からのパーティ取り込み（macOSのOCRに依存。サーバでは動かない） |
| パーティの保存（複数）・切替 | 利用者による環境データの更新 |
| 選出予想・素早さ比較・ダメ計・対戦（逆算）・履歴・評価・タイプ相性 | Claude向けの state/ の書き出し（ローカル版だけ） |
| プランの上限（free のみ。数値は後で決める） | 課金（Stripe） |
| 利用規約・プライバシーポリシーのページ | メールのワンタイムコード（送信用SMTPの用意が要る。Googleの次に足す） |

## 公開前に決める必要があること（技術以外）

1. **環境データ（使用率・型）の出どころ**: 取得先（ポケモンバトルデータベース）の利用規約は「競合するサービスの運営・開発に関与する者によるデータ取得」を禁じ、データ整理の権利はサイトに帰属するとしている。公開サービスで使うには許可が必要（連絡先: X @pokedb_tokyo）。上位構築の公開データ（/opendata）は、アプリでの利用が案内されている（自分のサーバに一度ダウンロードして使う）。許可が取れるまでは「種族値からの推定型＋公開データ」で動かすことはできる
2. **ポケモンの名称・データの権利**: 名前・設定は各権利者に帰属する。無料のファンツールは多いが、課金を始める前に公式のガイドラインと他サービスの例を確認する
3. **ドメイン**、利用規約・プライバシーポリシーの文面（取り扱う個人情報はメールアドレスのみ、と書ける）。サービス名は「ギャクダメノート（Gyakudame Note）」に決定
